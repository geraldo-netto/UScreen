# T308 — AppImage packaging and process lifetime

The release inventory now replaces `.deb` with an AppImage and its required
corresponding-source archive. RPM, Arch and tar formats remain. The publisher
checks six payloads plus SHA256SUMS before publishing. No release, deployment,
tablet access or EVDI attachment was performed during this validation.

The [user guide](../appimage-plan.md) documents launch, explicit user registration,
updates, FUSE-free execution, migration and host integration requirements.
Each independently launched daemon invokes the stable outer image and owns its
extraction lifetime. A service is used only when its registration marker matches
that image. Installed image wrappers select extract-and-run for FUSE-free hosts;
manually extracted installations retain a persistent AppDir. User installation
preserves preferences and autostart intent, refuses a running daemon, and keeps
rollback data on failed directory replacement.

## Evidence and scope

The real image built in Debian 12 and passed a clean `debian:12` container check
without mounting host display/device paths. The test verified ELF resolution,
helper binding to bundled libevdi, CLI/status, stock FFmpeg encoding, ADB,
FUSE-free user registration, idle daemon start/stop and an Xvfb GUI window.
A second check launched the GUI and daemon through separate **actual AppImage
extraction runtimes**, closed the GUI, verified the daemon remained running,
and stopped it normally. The refusal helper was never invoked. This validates
userspace packaging, not physical capture, GPU-driver compatibility or tablet
performance.

Direct byte comparisons confirmed stock FFmpeg, ADB and libevdi were unchanged.
The source/notices inventory covers 200 Debian binary packages from 154 source
packages, 333 Rust crates, the pinned EVDI source, runtime source and five runtime
dependency source archives. Packaging rejects unavailable exact Debian sources,
source checksum mismatches, unverified tool inputs and unresolved ELF libraries.
An older cached build image initially lacked matching sources in current mirrors;
refreshing that disposable environment supplied matching packages and sources.

The AppImage is approximately 377 MiB and its source archive 831 MiB for this
validation snapshot. These include the stock FFmpeg dependency set and project
documentation; they are not minimal-runtime size claims. Exact sizes and hashes
are in [artifacts.json](artifacts/2026-09-19-appimage/artifacts.json).

## Permanent coverage

The release-inventory regression failed before the publisher change and passed
afterward. The normal Rust tooling suite invokes 18 AppImage tests and the
release regression. They cover dispatch, literal arguments, path spaces and
metacharacters, independent extraction cleanup, installation rollback, conflicting
autostart distributions, invalid paths, malformed metadata, dependency cycles,
ABI bounds, checksums and oversized downloads. Seeded invalid-metadata fuzzing is
bounded and repeatable. The portability CI performs the actual artifact smoke
and lifetime checks; offline package fixtures do not replace those checks.

The daemon suite passed 415 tests (three existing ignored probes), C/helper and
other daemon integration suites passed, and all 35 tooling tests passed after
updating release fixtures. Common and GUI suites passed under LLVM coverage.
Clippy, formatting, the MSVC all-target/all-feature check and the complexity
check passed; 4,306 maintained functions, including tests, were within the
maximum cyclomatic score of nine at this snapshot.

Scoped executable-line measurements:

- 34 new Python functions: at least 86.67%, combining unit tests and an instrumented
  real package build with coverage.py 7.15.2.
- Six new Rust launcher functions plus changed discovery/autostart/service
  functions: 86.67–100%, using cargo-llvm-cov/LLVM executable line records.
- Ten installer/service-writer Shell functions: all identified executable lines
  observed by Bash xtrace across the permanent tests. This is source-line
  execution coverage, not branch coverage.

[Compressed logs and per-function results](artifacts/2026-09-19-appimage) retain
the measurements. T497 remains open for project-wide measurement and enforcement;
these scoped results do not establish coverage for the entire project.
